## 2. 控制与配置审查

三个示例共享同一播放和约束核心；准备均35轴回中，播放轴集合分别26/28/29。例1不启动相机，例2不发送颈部位置，例3保留既有眼颈协调。保持轴仍参与反馈检查。原启动恢复、舌部卸载及颈部扭矩保留机制沿用。

`hardware.json`是运行速度、软件加减速和硬件调参唯一来源；启动设置、跟踪器和运行profile据此生成。`telemetry.json`是软件告警策略来源，已去除新硬件配置中的旧350/60冗余阈值；运行时按同一策略生成阈值。作品清单只保存路径和来源。倍率适用轴作为配置列出，默认1.0，不改变当前轨迹。

视觉子进程不控制串口。会话锁覆盖准备和播放；自行启动的相机在结束或异常后清理，外部相机服务仅在配置哈希匹配时复用。源表达数据不被静音识别、额外眨眼或强制收口逻辑改写。
