# 上游轨迹规划（后续功能，尚未实现）

2026-10-27｜本轮只撤销16计数发送死区，并将ID32 PID的P从32降为16。D/I=32/0、硬件加速度128、速度上限600、目标低通150ms、回中至少3秒保持。先由用户观察；如果抖动消失，暂停本功能开发。

## 1. 目的与范围

只对颈部ID32生成连续的运动参考，改善启动、缓慢跟随、换向和回中的目标突变。不改变人脸检测、眼颈控制权、眼球运动、表情素材、标定或设备保护，不将轨迹连续性等同于实际机械平顺。

## 2. 后续设计

- 使用单轴在线轨迹生成器，持续维护参考位置、速度、加速度，约束速度、加速度与jerk；先不引入snap，不恢复原64计数/秒²限制。
- 跟踪使用现有控制器的期望速度；回中使用2047及最终静止目标。模式切换继承当前参考状态，不每帧重置或重启回中时长。
- 轨迹层接管ID32的目标平滑，避免与150ms位置低通重复叠加。保留图像端必要的噪声处理，并在接近行程边界时提前制动。
- 输出按现有60Hz控制循环发送整数位置，不按16计数等阈值合并。不声明舵机内部曲线、实际加速度或机械jerk因此被精确控制。
- 软件加速度/jerk以计数/秒²、计数/秒³表示，与41的原始值128分开；参数需要结合有效硬件响应和实际日志筛选。

## 3. 按需开关

未来实现时提供明确开关，名称为“上游轨迹规划”，默认关闭。拟由`neck.upstream_trajectory.enabled`控制，仅为接口设计，当前配置和代码均没有此入口。关闭时使用既有150ms位置低通链路；开启时由轨迹生成器接管。切换必须有明确的状态交接，不允许位置或速度跳变。

## 4. 验证顺序

先用现有日志离线回放筛选参数，核对位置边界、参考速度/加速度/jerk、控制周期变化、跟随滞后和目标切换连续性；不把固定输入回放当成相机闭环效果预测。

再现场分别验证启动、缓慢跟随、左右换向、丢脸回中及重新捕获，记录参考目标、实际发送值、编码器与用户观察。单独验证通过后再与完整音频表情联合验收。
