# 语音易中断、播放缓冲超限与方言效果复盘

## 1. 现场证据

会话：`outputs/p1/20261110_184430_782988`，18:49:13语音进程报告`Playback backlog exceeded its bounded buffer`，随后管理器退出。

| 项目 | 日志测量／现场反馈 |
|---|---|
| 云端轮次 | `smart_turn_v2`，服务器确认threshold=0.5 |
| 本地候选打断 | 收到speech_started即暂停，40ms淡出；有效话轮确认才丢弃，turn_invalid则恢复 |
| 身份重置 | 本会话3次identity_uncertain；18:14会话15次，18:31会话4次 |
| 停播回复 | 已记录83个0.4秒音频包，共33.2秒；第84包进入接收统计后越限 |
| 包到达时间 | 前33.2秒音频约3.49秒到达；云端可快于实时生成，不表示声卡慢 |
| 最后有效缓冲 | 30.0秒，旧上限正好30秒 |
| 本句首声 | 首包后约0.34秒首DAC，说明已实际开始播放，并非整句没有生成声音 |
| 声卡／口型服务 | 音频callback_warning_count=0；口型error=None、prebuffer_timeouts=0 |
| 方言 | 工具请求成功，但现场四川、陕西、上海大多仍为普通话发音；广东话部分正确 |

因此，本次直接退出原因是正常语音突发撞上错误偏小的应用缓冲限制，再被上层当作云端不可用；没有证据显示本次是USB声卡卡死。生成完成文字也不证明音频播完。另有身份检测抖动重建会话造成真实清音频，不能全部归因于用户打断或AEC。

## 2. 修复与当前参数

| 项目 | 修复后的行为 |
|---|---|
| 云端VAD threshold | 0.5→0.65，降低对微弱声触发的敏感程度；握手核验服务器确实接受 |
| 本地候选打断 | 180ms候选保持后暂停；短暂候选若先被判turn_invalid则不造成停声 |
| 确认的有效话轮／工具停止 | 不等待180ms，沿用原有确认取消与状态管理；仍由Qwen决定意图 |
| 取消与恢复 | 有效话轮丢弃旧句，判无效恢复原音频；不能复活已停止或已被服务器取消的句子 |
| 播放缓冲 | 单位为48k输出采样，统一配置上限120秒，约23MB PCM，仍有界 |
| 真正超限 | 只取消超限回复并拒绝其迟到包，给出语音告警；麦克风、交互状态及下一句继续 |
| 口型帧保留 | 由同一音频缓冲配置推导120秒＋2秒余量；避免快生成的长句挤掉尚未播放的开头帧 |
| 身份不确定宽限 | 3秒→15秒；宽限期间不把未确认者当熟人，不给未确认者检索个人记忆 |
| 方言偏好 | 仅身份不确定重建个人会话时保留公共偏好；确认换人／离场仍恢复默认 |

云端阈值依据[官方客户端事件](https://help.aliyun.com/zh/model-studio/fun-audiochat-client-events)：值越高越不易被微弱音触发。`silence_duration_ms=3000`虽在服务器回包中出现，但官方说明对smart_turn_v2不生效，未将其作为降低打断的措施。180ms是本地候选停声保持时间，不是语义确认时长或全链路延迟保证。0.65与180ms为待现场验收的初始整定值。

标定、舵机限位、速度、加速度、扭矩、眼颈轨迹、音频AEC及声卡设备不变。麦克风／声卡失效、串口看门狗及真实设备故障仍按原策略处理；这里只区分单句内容过长与基础服务故障。

## 3. 方言限制

见[方言说明第4节](../SPEECH_DIALECTS.md#4-现场发现与音色限制)。当前龙安洋的官方类别只承诺普通话；不能在保留此音色的同时保证所有方言地道。用户随后明确同意方言模式使用许南川，普通话保留龙安洋。新增受控音色重连，同一方言音色下改会话指令；近期文字上下文与本地音频／机器人资源保留。

实际云端、合成文字与虚拟音频输出探测验证：普通话→四川话使用许南川并收到音频；四川话→上海话不增加连接；恢复普通话重新确认龙安洋并收到音频。全程未打开本地音箱／麦克风／相机／串口，音频输出租约对象保持，近期合成聊天背景续接；这不是实际声音或物理口型验收。报告位于`outputs/diagnostics/dialect_voice_switch_20261110/result.json`。

四川话在许南川明确8类清单之外，必须单独试听，不能用重庆话冒充已验收的四川话。另已准备四种短试音文件，位于`outputs/dialect_audio/comparison_20261110/`。

## 6. 19:46服务端InternalError与有限恢复

会话`outputs/p1/20261110_192039_659437`运行约25分钟后，19:46:09回复`resp_OWaJKCOtQ2BVDRT1lArv2`以`response.done: failed`结束，随后云端明确返回`InternalError`及生成响应时内部错误消息。该回复没有音频，产生空白文字回调。与18:49播放缓冲超限是两种不同故障；日志不足以定位供应商内部的具体故障原因。

[官方WebSocket错误处理](https://help.aliyun.com/zh/model-studio/audio-realtime-websocket-access)说明服务端错误可能终止连接，因此不在出错会话中盲目重发。现在仅对明确的`InternalError`、`ServiceUnavailable`重建语音连接，配置唯一位于`configs/perception/realtime_voice.json.service_recovery`：60秒窗口最多重连3次，退避0.5／1／2秒，第四次同窗口错误即报告失败并按原流程退出。成功握手不清空该窗口计数，防止“刚连上又报错”无限循环；认证、参数、设备、串口及其他未知错误不纳入此重试。

保留当前状态、近期文字上下文、已选音色／方言、麦克风、AEC、扬声器租约与机器人工作进程。不自动重放旧用户话语、节目点播或表情动作。恢复后日志报告“连接已恢复，请继续说话”，保持安静，收到新的speech_started才重新允许回复及控制工具；read-only状态查询仍可用。临时重连期间麦克风仍采样，云端尚未连接时不能识别新指令，不宣称无缝监听或零延迟恢复。故障回复及其尾音取消，空白转写不再打印“小帅：”。

新增故障注入覆盖真实收包分支、连接恢复、原音频租约保持、历史保留、禁止旧工具重放、新发声恢复、连续错误耗尽、无效参数／密钥不误重试，以及握手阶段的明确服务端错误。当前实际云端探测可连接并确认5项工具，不打开设备；不能因此保证供应商以后不会再出InternalError。现场仍需重启服务加载修改。
