# 墨甲本体、数据链路与标定

版本0.2｜2026-10-26。以下以当前装配、最终标定及已接受参数为准，部件额定规格不是整头表现保证。

## 1. 本体组成

本体由35只舵机、传动/牵引结构、仿生皮肤、眼球/眼睑、3轴颈部，以及双眼内的两只USB相机构成。主机通过USB串口与本体控制链路通信；相机通过USB提供图像。示例一次使用一只相机，默认右眼随ID23转动，左眼参考ID8。没有双目测距或双目融合。

本体供电入口、USB适配器和TTL/RS485转换按实际装配连接。单个舵机的电压范围不能代替整机电源要求，供应商参数以准确子型号为准。

## 2. 表情如何到达皮肤

1. 客户输入命名表情权重，或提供现有61通道文件。
2. 按名称和语义适配到基础表情；眼球/头部角度字段单独处理。
3. 最终标定给出每个基础表情在权重1时影响哪些轴及对应位置。
4. 以零权重中位2047计算偏移，按既有合成规则组合共享电机的表情。
5. 跟踪模式接管其拥有的眼球和颈部轴，其他轴保留表情轨迹。
6. 对目标施加软件范围、速度/加速度约束，跟随音频时间轴发送。
7. 舵机驱动机械传动和皮肤，反馈参与运行检查。指令位置与实际皮肤形变之间存在机构、摩擦和弹性影响。

### 2.1 2047不是最小值

2047是本机已经确认的零权重中位，位置可向两侧变化。例如最终标定中`BrowDownLeft`包括ID2=2300、ID3=2098、ID4=1954。ID2在权重0时2047，权重1时2300；ID4则朝更小计数运动。

只考虑一个表情时：

```text
目标位置 = 中位 + 权重 ×（标定端点 − 中位）
```

软件对单轴多个表情采用现有`bounded_weighted_deltas`：累计带权偏移后除以`max(1,参与权重之和)`，再叠加中位并限幅。眨眼具有独立的眼睑合成处理，眼神与眼睑的重复来源按既有规则排除。不同表情权重之和不要求为1；不能把多个表情的最终位置直接相加。实际实现见`src/vivis/motion/mapping.py`。

### 2.2 52表情、61通道与35轴

标定文件定义52个基础表情；作品61通道包含这52维，加3维头部旋转和左右眼各3维旋转。旋转字段采用原有导出约定（弧度），不是0–1表情权重，按`configs/schemas/blendshape_channels_61.csv`核对顺序。不能因为另一个模型也输出52维就直接接入。

当前最终标定覆盖30轴，3个颈部轴另行控制；ID9、24未映射，不参加作品位置发送。完整35轴仍纳入准备和回中清单。空映射表情不产生额外轴运动，不代表已实现该通道。

## 3. 标定文件和参数文件分别做什么

`configs/robots/mojia/calibration.json`为唯一最终标定文件。结构示例：

```json
{"shape":"BrowDownLeft","posSize":3,"positions":[{"id":2,"position":2300},{"id":3,"position":2098},{"id":4,"position":1954}]}
```

| 数据 | 职责 | 不代表什么 |
|---|---|---|
| 最终标定 | 表情名→轴ID及表情端点 | 不独立定义中位、速度或机械安全范围 |
| `hardware.json` | 轴中位、型号、设备范围、软件范围、运动参数 | 单轴范围不保证所有组合都可达 |
| `tracking.json` | 图像误差、眼球端点、眼颈协调参数 | 不定义第二套电机速度/PID |
| `telemetry.json` | 软件告警及连续异常样本策略 | 不覆盖设备固件保护 |
| `homing.json` | 缓慢回中速度和已验证的机构恢复关系 | 不重新生成表情 |

### 3.1 建议标定过程

1. 核对装配和轴ID，读取型号、工作模式、设备限位及当前位置；先保存原参数。
2. 建立自然中性姿态。当前本机各轴中位2047已确认，换本体或重新装配不能直接视为仍然成立。
3. 小幅单轴观察运动方向、牵引区域及机械范围，记录方向和适用位置范围。
4. 逐个基础表情调整相关轴，记录权重1的端点；多轴共同组成一个表情是正常的。
5. 检查0、0.25、0.5、0.75、1等中间权重，再检查常见表情组合及回中。
6. 保存标定与对应硬件配置的版本、哈希和现场记录；重新生成/核验派生轨迹后再播放。

软件检查`shapeSize`、`posSize`、重复通道、轴ID和数值范围；实际机构与皮肤效果仍需现场确认。本轮整理不提供自动扫满机械极限的程序，也不重新标定本体。

| STS3032 | 30只：2–30、36 | 磁编码位置控制、TTL串行总线，主要承担面部细部及眼球驱动 |

## 5. 通信与内存表

- [飞特FT-SCS通信协议](https://ftservo.github.io/ftservo-wiki/reference/protocol/ft-scs/)；[原官网协议页面](http://doc.feetech.cn/#/f?q=2506ba160b93)。
- [STS内存表解析](https://ftservo.github.io/ftservo-wiki/reference/parameter/memory-sts/)。
- [SMS内存表解析](https://ftservo.github.io/ftservo-wiki/reference/parameter/memory-sms/)；[原官网SMS手册](http://doc.feetech.cn/#/f?q=2602a06ca658)。
- [官方SDK地址定义](https://github.com/ftservo/FTServo_Arduino/blob/main/src/SMS_STS.h)、[SM45BL厂家规格书](https://www.feetechrc.com/Data/feetechrc/upload/file/20210630/6376066619149072575092101.pdf)。

ST/SMS通用协议框架相同，不代表所有寄存器语义、单位、出厂参数或固件行为相同。当前驱动使用本机核验的地址布局、低字节在前，启动时核对型号、相位和限位。对换型号应重新验证。

| 本机地址（十进制） | 用途 | 说明 |
|---:|---|---|
| 40 | 扭矩开关 | 与位置发送分开管理 |
| 41 | 硬件加速度 | 0需结合固件及86等出厂值解释 |
| 42–43 | 目标位置 | 当前位置反馈在56–57 |
| 46–47 | 运行速度 | 不等于所有型号的出厂最大速度限制寄存器 |
| 60–61 | 负载反馈 | 不可直接当机械扭矩或电流 |
| 62/63 | 电压/温度 | 按型号单位解释 |
| 65 | 状态 | 使用对应型号状态位定义 |
| 69–70 | 电流反馈 | 需核对型号支持和量纲；当前播放轮询不默认采集电流 |

位置发送采用广播ID254的同步写`0x83`，每轴包含自己的ID和目标，不是让所有轴去同一个位置。反馈用单轴READ`0x02`短请求，分步读取位置、负载、电压/温度和状态；在控制剩余时隙调度，不为每帧同步读取全部35轴。启动快照单独执行，按2字节分段读取完整配置和状态。字节报文示例及生成函数见`hardware/feetech/protocol.py`中的`goal_packet`和`packet`。

SM45BL固件2.53的41=0与倍数寄存器组合尚缺完整物理换算核验，需先向厂家核验该固件的物理解释，再设计动态响应试验；本教程不宣称某个未经测量的物理加速度。
