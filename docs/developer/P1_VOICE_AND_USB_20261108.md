## 2. 为什么没进入表情跟随

依据`outputs/p1/20261108_103017_380076/`中的事件、ASR日志与内核USB日志：

| 本机时间 | 证据 |
|---|---|
| 10:37:03 | DOV所在USB1-4.2复位，端点无法设置／读取48000Hz采样率 |
| 10:37:04 | USB接口设置失败（−32），设备断开 |
| 10:37:06 | ASR抛出`Microphone watchdog: no fresh capture frames`，管理器停止当前运动子任务后退出 |
| 随后 | DOV多次重新枚举／断开，最终出现−71及无法枚举；检查时音箱、相机和串口仍在，DOV不在设备列表 |

管理器没有收到“表情跟随”的最终识别事件，不能把这次未切换归结为表情跟随路由失败。原退出消息只保存在文件里，不够直观；现在识别子进程会发送结构化`asr_error`，终端打印具体错误、日志位置及保持扭矩的停止行为。

先插紧DOV或更换USB口、线缆，确认设备能稳定枚举再重启P1。现有证据定位到USB／采音层，不能进一步断定一定是供电、线缆、集线器或设备固件中的哪一种。不会靠延长看门狗或在没有麦克风时继续运动来掩盖问题。

```bash
lsusb
arecord -l
```

“你看”“表帅”按用户反馈记为本次唤醒误识别，第三次“小帅”成功。没有保存原始麦克风波形，且当次USB不稳定，先恢复设备再评估唤醒；不据此添加高误触发的谐音词或常用词。后续可单独评估轻量关键词唤醒。

## 3. 模型和语言标签

旧音频采样率24kHz，播放器按比例重采样至48kHz音箱，持续时间保持，未发现降速播放代码错误。旧音色的口音、韵律不能仅靠基频或ASR回读判断；这次以现场试听为准。

[Qwen官方模型](https://modelscope.cn/models/Qwen/Qwen3-TTS-12Hz-0.6B-CustomVoice)提供Dylan年轻北京男声音色。但其官方包装器会在Chinese／Auto时根据`spk_is_dialect`覆盖语言标签，Dylan对应`beijing_dialect`。只设置`language=Chinese`不能去掉这个强制方言选择。

适配层的`force_standard_chinese=true`在单次生成期间将当前音色的该标志设为False，选择模型的标准中文标签，生成后在`finally`中恢复原字典。它不改声线嵌入、权重文件或磁盘配置；这一组合是经用户实际试听接受的生成设置，不声称官方Dylan预设本身就是普通话音色。

| Orin本地首次试听 | 模型加载 | 合成耗时 | 音频时长 | 用户反馈 |
|---|---:|---:|---:|---|
| 原Dylan北京方言标签 | 12.57秒 | 132.70秒 | 5.28秒 | 比之前好，但北京口音太重 |
| Dylan＋标准中文标签 | 12.65秒 | 166.29秒 | 6.72秒 | 合适，采用 |

两次均为CPU／FP32、6线程。这些是离线合成耗时，不是播放速度或已达到实时TTS的证据。当前系统仍为缓存播报，尚无A2F同步口型；开放对话与在线TTS性能属于后续②交互态工作。

## 4. 缓存交付与复现

活动配置仍在`configs/perception/speech.json`，ASR的Python和模型保持原值；TTS使用单独环境，避免影响ASR和主控制环境。

| 内容 | 位置 |
|---|---|
| 已交付七条播报、文本与校验元数据 | `assets/speech/xiaoshuai_qwen3_mandarin/` |
| 模型文件清单、大小和SHA256 | `native/speech/qwen3_tts_sources.json` |
| 可选TTS生成环境 | `outputs/tts_qwen/venv/` |
| 可选模型权重 | `outputs/tts_qwen/model/` |
| 独立准备工具 | `tools/setup_qwen_tts.py` |

整套缓存由用户原4090服务器的隔离任务目录加速生成，采用同一模型、普通话标签与FP32，随后传回Orin。服务器原有工程和环境未被替换。实际生成设备记录在元数据中；播放缓存的语义校验不要求客户复制GPU、线程数或生成环境路径，但仍校验模型身份、语言、音色、普通话开关、文本、响度、来源清单和WAV哈希。

正常安装及运行只需已交付缓存，`setup_p1.py`通过校验后跳过大模型安装。客户不需要服务器或Torch来播放提示音。以下命令仅做文件检查，不打开任何设备：

```bash
.venv/bin/python -m vivis.speech.prompts --check-cache
.venv/bin/python -m vivis.interaction.programs dialogue --check
```

只有需要重新生成时才运行：

```bash
python3 tools/setup_qwen_tts.py
PYTHONPATH=src outputs/tts_qwen/venv/bin/python -m vivis.speech.prompts --prepare
```

独立工具从ModelScope下载固定哈希文件；默认CPU生成以便Orin复现，不承诺实时速度。`--prepare`会按活动配置更新缓存文件，需检查Git差异。七条运行提示默认生成；加`--diagnostics`才额外生成ASR测试短句。

试听其他命名音色：

```bash
PYTHONPATH=src outputs/speech/venv/bin/python tools/audition_voices.py \
  --voice Dylan --voice Uncle_Fu --output outputs/speech/qwen_comparison
```

工具自动转交独立TTS环境，只导出WAV，不播放或驱动设备。普通话开关及原生语速来自活动配置；0.6B适配层不接受假装生效的任意速度值。
