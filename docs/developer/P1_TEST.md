# P1三级状态现场测试

## 1. 当前功能

原“等待节目选择”与“互动待机”现合并为②交互态；①是真正待机，③是节目任务。完整状态图、口令及配置见[三级会话说明](THREE_MODE_SESSION.md)。

| 状态 | 视觉与动作 | 进入／退出 |
|---|---|---|
| ①待机 | 摄像头关闭，回中后低频眨眼；无眼颈追踪 | 启动默认进入；喊“小帅”唤醒 |
| ②交互 | 持续微笑0.50、自然眼颈跟随、短暂移开视线；支持固定身份／能力问答 | 唤醒、任务正常结束，或任务中说“停止／退出／不用播了” |
| ③任务 | 白骨夫人／魏总剧本预录播放，无实时A2F或微笑叠加；另有表情跟随 | ②中选择节目；可随时回②或① |

②／③说“待机、自己玩去吧、休息一下”等直接进入①。“停止”和“待机”现在有不同含义，旧测试不能再把所有退出词当成待机。麦克风由外层管理器持续持有；独立的视觉子程序不提供语音监听。

当前节目单恢复魏总剧本表演（wz2），与白骨夫人一起采用静态表情及音频；表情跟随保留实时模仿。没有开放式LLM对话、角色扮演、前台或文旅节目。真机口型饱满度等后续工作仍按已有标定／结构计划推进，本轮不改运动参数。

## 2. 安装与离线检查

```bash
cd /home/james/project/Vivis-delivery
.venv/bin/python -m vivis.interaction.programs dialogue --check
```

应显示三个`modes`、`initial_mode: standby`、`wake_words: [小帅]`、三个节目及`hardware_opened: false`；本机`missing_dependencies`应为空。这一步不打开真实设备或识别模型。

首次安装可选依赖，或提示音缓存不匹配时：

```bash
sudo apt-get install -y libspeexdsp1 sox
python3 tools/setup_p1.py
```

本轮两份预录节目不需要实时A2F；交互和表情跟随需要Face Landmarker依赖。系统播报仍为缓存TTS，没有同步A2F口型，后续单独迭代。当前Orin均已准备。当前暂选中文男声66（zm_020），语速1.05；相对歌曲的响度及句间停顿保留；唤醒应答为“在呢，你说！”，在交互准备完成后播放。配置或提示文本更改后须重新生成缓存；运行时播放缓存，不在运动线程生成TTS。

## 3. 先测语音：不驱动机器头

```bash
.venv/bin/python -m vivis.interaction.programs dialogue \
  --listen-only --seconds 90
```

等“麦克风已就绪”后逐句说，句间停顿约1秒：

1. “播放白骨夫人”：保持①，尚未唤醒。
2. “小帅”：进入②的路由状态。
3. “你是谁”“你能帮我做什么”：识别为固定问答。
4. “播放白骨夫人”：进入③的路由状态，不实际播放。
5. “不用播了呀”：回②。
6. “自己玩去吧”：回①；此时直接问“你是谁”应被忽略。
7. “小帅，开始表情跟随”：同句唤醒并选节目；“退出哟”回②。
8. “播放魏总剧本”：进入③；“停止”回②。
9. “待机哈”：回①。

这一步只验证真实麦克风、ASR与状态路由，不打开音箱、相机或舵机。当前DOV输入为48kHz双声道中的第0通道，转换为16kHz识别，保留原回声处理。单次识别成功不能当作已完成现场唤醒率、误唤醒率和双讲验收。

## 4. 完整流程

确认机器头上电、颈部可靠支撑、串口／相机／音箱／麦克风就绪，退出占用设备的旧程序，再运行：

```bash
.venv/bin/python -m vivis.interaction.programs dialogue \
  --robot configs/robots/xiaoshuai/robot.json
```

按[三级会话说明第3节](THREE_MODE_SESSION.md#3-启动与测试)操作，重点检查：

- ①中预览服务不运行，不追踪经过的人。
- 唤醒后才进入②，准备成功后短应答，预览`http://127.0.0.1:8765/`可用。
- ②中保持微笑5～10秒，机器人渐起并持续回应，用户放松后有余韵再收回；眼神偶尔短暂移开，但笑容可保持。
- ③结束或说“退出”回②，不误关到①；说“自己玩去吧”才回①。
- 所有状态切换中麦克风进程PID保持不变，直到管理器退出。

当前身体保护、自检／型号／限位／姿态校验及停止保持扭矩行为保留；首次启动回中仍60计数/秒，运动会话就绪后的正常切换暂用120计数/秒，并按本体及受限恢复要求裁剪。小帅ID9、24仍排除，实际30轴；这些是本体层配置，不是向两轴发送位置0。若自检失败，管理器播报一次故障后退出，不因ASR仍识别出字就继续运动。

语音退出节目不退出管理器。Ctrl+C退出整个管理器，停止发送并保持安全姿态和扭矩，同时释放麦克风与当前视觉实例。

## 5. 回声与打断专项

持续开麦不等于已验收开放式全双工。当前日志证实AEC启用，但自播残响仍可被识别，不把组件开启当作消回声验收通过。本阶段保留提示音轮次抑制及原AEC；先等短提示结束后选择节目。停止／待机控制词优先处理。

1. 用户不说话，只播放歌曲及菜单，检查是否误触发选择、退出或待机。
2. 在预期使用距离和正常音量下，分别说“停止当前节目”“不用播了”“进入待机”，每种重复数次。
3. 对照单词“停止”与完整短句，记录识别原文及状态目标，避免只看意图标签。
4. 保留`asr.log`和`events.jsonl`中的`reference_coverage`、近端／参考RMS及两套完整识别假设。参考覆盖不等于已消除回声，需联合误触发和双讲结果判断。

若听不清、误唤醒或切换错误，先保留日志，再调整距离、朝向或麦克风位置；不要用不断添加未经验证的谐音词掩盖识别问题。

## 6. 独立调试和日志

```bash
# 只测②的视觉行为，无语音监听
.venv/bin/python -m vivis.interaction.programs interaction \
  --robot configs/robots/xiaoshuai/robot.json --seconds 180

# 只测①的低频眨眼，无语音监听
.venv/bin/python -m vivis.interaction.programs standby \
  --robot configs/robots/xiaoshuai/robot.json --seconds 60
```

独立命令不能与管理器同时运行。当前配置分别为`interaction.json`和`standby.json`；②可用`--smile off`或`--tracking off`作诊断对照，①固定不启用视觉。表情及注意力细节见[交互行为说明](STANDBY_BEHAVIOR.md)。

每轮管理器在`outputs/p1/时间戳/`记录有效配置、`speech_effective.json`、事件与子程序日志；`outputs/runtime/program_status.json`记录真实当前模式、最新请求模式、阶段、自检、唤醒词和麦克风PID。切换中`mode`与`desired_mode`可以短暂不同，只有下一实例就绪才表示转换完成。

子会话保留准备、反馈、最近600条控制记录及表情统计，默认不持续录制麦克风PCM。`attention_aversion_count`和`glances`是上游计划次数，不能直接当作编码器或皮肤实际完成次数。故障退出不会自动重试运动；排查后重新启动。
