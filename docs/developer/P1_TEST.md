确认小帅上电，颈部可靠支撑，串口、眉心USB相机、音箱和麦克风已接好；先退出之前独立运行的示例。启动后会按原流程以60计数/秒上限平滑回中。

```bash
.venv/bin/python -m vivis.interaction.programs dialogue \
  --robot configs/robots/xiaoshuai/robot.json
```

听完欢迎语后选择节目。待机及人脸节目运行时，Orin本机监控地址为`http://127.0.0.1:8765/`。待机现在会跟随画面内人脸并回应微笑；人脸离开后回中，回中完成后轻微游视。相机、UDP接收器和串口控制权由当前子节目持有，切换时先释放旧实例，不同时启动两套控制器。

当前欢迎、菜单和身份等提示使用Kokoro中文男声58（`zm_009`），已重新生成。响度以白骨夫人原音频为参照，目标低3 LU；受−1 dBTP峰值限制，当前主要提示实际约低4～5 LU，现场听感仍需确认。提示音只在安装／准备时生成与处理，运行时直接播放缓存；不调系统音箱档位，也不修改歌曲文件。配置更换声音或音量后须重跑`python3 tools/setup_p1.py`，管理器会拒绝旧声音缓存。

提示语按语义分句合成，分句之间显式保留180ms停顿、句末420ms停顿；男声音色与响度策略保持。改变文本或停顿配置后，重新执行`python3 tools/setup_p1.py`生成缓存，运行时不做TTS推理。

自检／节目失败会中断未播完的欢迎语，播报一次故障提示，然后退出管理器并释放麦克风；不会继续识别、切换节目或自动重试。按终端日志检查后再重新启动。位置越限与已采用连续4次确认的温度／电压等传感器故障是不同检查：例如ID33在未使能时1539低于设备下限1600，不能直接跳过位置检查。机构确认与必要恢复属于本体准备流程，不通过扩大上游目标或硬件限位解决。

当前`p1.json`的`overlap_warmup=true`：视觉/A2F在无舵机控制权的工作进程中预热，与原有自检、参数核验、60计数/秒五次曲线回中并行；回中及所需模型、最新视觉目标都就绪后才启动节目。出现`WARMUP START/READY`可观察准备进度。没有缩短或跳过自检，也没有提高回中速度。较大行程仍需要数秒；可将此配置设为`false`，对照原有串行准备流程。

白骨夫人实时口型默认使用随包的`assets/works/0001/inference_vocals.wav`（原工程分离人声），音箱继续播放`audio.wav`完整原曲。两轨同为1806294个16kHz样本，已核验共同起点和分布于全曲的零时差相关；路径／哈希及对齐报告登记在作品清单中，两台本体共用。P1管理器和独立`singing`入口均自动选择人声，不读取预录表情；原来的三个静态示例仍播放其预录轨迹。启动日志`AUDIO INPUT`会打印推理与播放的实际文件。`--inference-audio`仅在显式对照时覆盖推理音轨，不改变音箱播放内容。

本阶段已结束口型软件调优。白骨夫人的口部／张嘴／圆唇源通道默认增益仍为1.0，11个有效口部轴硬件速度900计数/秒、加速度原始值0；没有新增口部软件限速或静音归位处理。歌曲中眼颈跟随继续工作，实时微笑回应默认关闭。预设歌曲、朗诵及剧本类内容按相同默认策略处理；未来注册到`runtime_a2f`路径的内容没有显式`realtime_response: true`时也关闭回应。这不是新增朗诵或剧本节目，当前节目单仍只有白骨夫人和表情跟随。

待机的微笑回应由`standby.json`配置，当前增量0.50、通道为MouthSmileLeft／Right及CheekSquintLeft／Right；不改变源通道1.0倍率。待机使用`face_selection=largest`，微笑识别与眼颈跟随处理同一个已选择的人脸ROI，画面中还有其他脸也不会直接禁止回应；歌曲显式开启微笑的诊断仍保留原单脸策略。待机采用持续回应：确认微笑后约0.4秒渐起，用户仍在笑时保持，确认放松约0.8秒后用约1秒收回；短暂丢失观测有缓冲，控制端拒绝过期或非法事件。歌曲显式诊断的原短笑脉冲与冷却不变。待机没有歌曲口型任务，因此不保留歌曲关键口型轴的专用控制权；新增可回应的轴仍由本体标定决定，位置和硬件参数不修改。眼颈复用当前本体已配置的控制器：小帅独立32／33／34，墨甲按并联配置选择。回中仍使用原60计数/秒流程。

小帅颧骨ID9、24暂时排除，完整模式实际准备30轴。这是按用户要求临时不发指令，不是向舵机发送位置0。每遍准备时可直接看到：

```text
SELF-CHECK START 舵机自检：30轴；排除[9, 24]（不检查、不发送指令）
SELF-CHECK PASS 舵机自检通过：30/30轴；排除轴不计入通过数
HOME 30 AXES START speed_cap=60
HOME COMPLETE; original speed settings restored
PREPARE COMPLETE 自检通过，参数核验及回中完成
```

`SELF-CHECK PASS`表示回中前的设备读数／型号／限位／姿态及配置计划检查通过；只有`HOME COMPLETE`及`PREPARE COMPLETE`才表示参数核验和实际回中完成。若出现`SELF-CHECK FAIL`会直接显示失败轴及原因；后续参数写入或回中失败则显示`PREPARE FAILED`及对应阶段。管理器已故障时再说节目名，会提示“未执行”，须排查后重新启动，不能把识别成功当成动作成功。

| 顺序 | 说话或观察 | 验收重点 |
| --- | --- | --- |
| 1 | 暂不选择，面对相机微笑并缓慢左右移动；随后离开画面 | 待机微笑回应和眼颈协同跟随；人脸离开后平滑回中、恢复低频眨眼及小幅游视 |

| 3 | 歌曲正在出声时说“停止”或“退出吧” | 程序识别到待机意图后取消当前节目；音频做短淡出，动作随后按既有慢速回中流程进入待机 |
| 4 | “开始表情跟随” | 表情、眼球、颈部跟随正常，不残留上一首歌的声音或口型 |

可再分别测试“结束、退出、待机、休息一下”。表情跟随默认最多10分钟，期间可随时用退出短句结束。明确再次选择正在播放的节目，会从头重新准备和播放；同一条识别结果不会执行两次。

### 4.1 先单独调试互动待机

先退出语音管理器和其他示例，再运行：

```bash
.venv/bin/python -m vivis.interaction.programs standby \
  --robot configs/robots/xiaoshuai/robot.json --seconds 120
```

默认同时开启眼颈跟随及持续微笑回应，微笑增量0.50。等待`STANDBY START`后：

1. 正对相机，放松→微笑保持1～2秒→放松，重复几次，观察嘴角和眼角是否自然起落。
2. 缓慢左右、上下移动并轻微歪头，观察眼球及三轴颈部配合。不要将图像中的检测框跟随直接当作真机完成了动作。
3. 离开画面，观察眼颈平滑回中；回中完成后恢复轻微左右游视。眨眼继续保持低频。多脸场景会继续选择最大人脸，测试无人回中时需确保画面中不再有其他人脸目标。
4. 运行期间用Ctrl+C停止，随后重新启动一次，检查相机、预览和控制权正常释放。

单次对照开关：`--smile off`只关微笑，`--tracking off`只关眼颈追踪；两者都off可恢复无相机的原待机动作。`--smile-strength 0.3`可作单次幅度回退对照，不写回默认文件。用户持续微笑时应保持回应，放松后收回。有人脸时短暂移开视线的注意力节律尚未接入，设计及分步验收见[互动待机行为设计](STANDBY_BEHAVIOR.md)。

该独立命令不监听语音，Ctrl+C停止；不要与P1管理器同时运行。待机运行不启动A2F、音箱或麦克风。可在`summary.json`核对`social_response_ticks`、`social_envelope_peak`和`social_target_delta_peak_by_id`；这些分别是回应采样周期、包络和名义目标增量，不是皮肤动作测量。

独立`singing`也默认关闭微笑，显式`--smile on`仍可作资源／算法诊断；P1中的歌曲不随待机的微笑开关自动开启。

## 5. 回声和打断专门测试

本版把原计划P4中的“播放中用明确短句退出”提前接入：持续采音，接收实际声卡输出PCM的带时标参考，做回声处理、语音分段和最终识别。本轮不把一般VAD声音活动直接当作停止命令，也不执行变化中的识别中间文本。

1. 不说话，播放至少30秒：确认不会因为机器人自己的声音而误切节目或停播。
2. 在预定使用距离、通常播放音量下，连续做5次“播放→说退出→待机”的测试。
3. 分别观察较响乐段、较轻乐段和表情跟随的无音频场景，记录哪些短句、距离或音量容易失败。

合成线性回声测试约29dB抑制，以及时间戳插值／采样时钟偏差测试，不能代替上述现场双讲验收。当前“停止／结束”等真人短词还存在误识别记录；不要把这一项记作已通过，也不要为了通过而扩大舵机保护阈值。

音频识别与控制本身都存在延迟；40ms是识别命令生效后采用的淡出长度，不是“从用户开口到停声”的总时间。淡出会等待声卡既有缓冲排出，最长等待有界；平滑回中还需要原有启动检查和与当前位置相关的运动时间。需要分别记录听见命令、声停、回中结束。

## 6. 日志与可配内容

每次启动会打印`outputs/p1/时间戳/`目录：

- `events.jsonl`：最终识别、路由、取消请求、子节目启动／结束等事件。
- `asr.log`：麦克风／识别进程错误；默认不保存持续麦克风PCM。
- `0001_standby.log`等：对应子节目的控制台记录。
- 各子目录：准备、回中和播放记录；`preparation.json`含`self_check`的检查轴、排除轴、结果／失败原因，以及`preparation_completed`；`summary.json`在管理器退出后记录最终状态。
- `outputs/runtime/program_status.json`：当前阶段及节目，供状态界面读取。

歌曲的`animation_summary.json`还记录实际源通道增益、微笑增量、回应控制周期数、实际映射目标增量峰值和A2F首段数据准备时间。这些是目标／软件观测，不代表皮肤已完成相同动作。

默认减少记录量，保留必要计数、告警、反馈及最近600次控制提交；不是完整全曲逐帧测量。需要排查具体播放问题时，可显式打开完整节目日志：

```bash
.venv/bin/python -m vivis.interaction.programs dialogue --diagnostics on
```
