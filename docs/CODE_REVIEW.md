## 已修复

1. **播放前校验不一致**：原先仅 `record_only` 校验轨迹数组和目标限位；`stop_on_fault` 的直接调用可能将越界目标送入渐进限速器。现在两种策略均在打开音频和串口前检查非空轨迹、维度、有限数、位置范围、帧率和重复 ID，并补充回归测试。
2. **干净检出无法测试**：测试原来读取本机歌曲输出和完整录制 CSV。改用三帧合成数据与仅含表头的 61 通道文件；旧标定移入测试样例，可选模型绑定测试在无模型时明确跳过。现有录音与生成文件未修改。
3. **外部依赖未固定恢复方式**：播放器依赖被忽略的 FTServo_Python。增加固定提交清单与恢复工具；最小 Python 依赖补齐 NumPy、SciPy、jsonschema。
4. **模型版本可能静默漂移**：下载工具原来每次取远程最新版本并覆盖清单。现在默认复用已保存快照，仅显式 `--refresh` 更新。TensorRT 安装改用六个包的版本与 SHA256 清单，免除对本机大型软件包索引的依赖。

## 2026-10-22 Jetson 播放迁移审查与实机验证

环境：Jetson AGX Orin、aarch64、Ubuntu 24.04.5 LTS、Python 3.12.3；沿用原小白和最终标定。此次验证范围是已有动作 JSON 与 WAV 的同步真机播放，不包含 Jetson 上重新执行 A2F 推理、模型构建或视频渲染。

变更：播放环境脱离 x86_64 CUDA/TRT 路径；Python 3.12 使用 NumPy 1.26.4；通过显式 `XIAOBAI_USB_SERIAL` 匹配转接器并定位唯一端口；权限恢复使用 sudo 调用用户；播放器可指定音频设备、缓冲和串口，颈部归位工具可指定串口。原转接器默认值、标定哈希、动作位置限位、限速及反馈策略保留。

审查补充：音频缓冲在运行时入口验证，拒绝非有限数、布尔值及范围外数值；增加模拟音频回归测试，确认 200 毫秒缓冲仍使用 DAC 输出时间作为动作时钟。未在本次提交中执行系统驱动切换；现有 WCH 驱动已可用。

实机结果：先停止占用串口的 `dms.service`；Windows 播放后重新扫描确认面部已使能且 ID25、ID26 回到允许范围。颈部经已有慢速归位工具将目标统一为 2047。USB 音频低延迟模式曾发生 `output underflow` 并触发停止，随后设置 `--audio-latency 0.2` 完整播放成功。现场操作员确认声音和面部动作正常。

- 输入：6774 帧、60fps，动作时长 112.9 秒，PCM16 单声道音频时长 112.893375 秒；标定 SHA256 与配置一致。
- 播放：60fps、100% 幅度、反馈只记录；`completed=true`、`full_clip_requested=true`，停止音频时间 112.893839 秒，发送 6773 帧、跳过 1 帧。
- 通信：日志记录 111 条损坏回复及 111 条读取失败记录，另有 1 条 ID26 无有效载荷通知；这些计数不能相加视作独立故障数。播放完成不表示零通信异常或逐帧机械到位。
- 本地证据：`outputs/xiaobai/0001_direct_20261022_160744_331871378/`。媒体、串口追踪和运行日志按原白名单留在本机，不提交。
