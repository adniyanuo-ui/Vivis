# 小帅（xiaoshuai）：配置与作品1

小帅：男性，28岁。舵机分布同小白，设备清单为ID2～34共33轴：2～30读数521，31～34由用户确认是SM45BL，读数11272。配置和标定保存在本目录，控制代码与墨甲共用。

**当前临时排除颧骨ID9、24**：用户确认这两轴硬件待优化，`robot.json`的`excluded_actuator_ids`是唯一排除配置。两轴不参与自检、参数写入、使能、回中、位置发送或反馈轮询；不发送位置0，也不改其EEPROM、原始标定或素材。三种模式实际准备23／27／30轴。硬件优化完成后再明确恢复配置；未检查的轴不计作自检通过。

## 1. 首轮播放：面部＋完整音频

在项目根目录执行：

```bash
./examples/01_face_control/run.sh \
  --robot configs/robots/xiaoshuai/robot.json \
  --work 0001 --repeat 1 \
  --mouth-command-mode lips-direct --mouth-speed 900
```

末尾加`--check`仅做离线检查。当前有效口部11轴硬件速度上限900计数/秒，预录示例表情/圆唇增益默认均为1.0；每遍先以不超过60计数/秒缓慢准备23个面部轴，再从头播放完整作品1。显示`ROUND 1/1 COMPLETE`为本遍正常完成。P1实时歌曲的增益独立取`configs/interaction/p0.json`。

示例1不打开相机。眼球7/8/22/23、未映射29和颈部32/33/34不参与本模式的回中、位置发送或使能。停止沿用最后合法目标，不突然卸载受力机构；小帅不执行墨甲专属ID29吐舌恢复或结束卸载。

首次联合验收原用颈部±80/±60/±40计数，用户反馈量程小且跟随慢，已明确要求扩大到最大硬限位。当前三轴指令与规划范围直接读取已复核的EEPROM上下限，删除了重复的小范围配置，不改设备寄存器。表中是允许范围，不表示人脸每次移动都会走完整个行程。

ID32回中前曾在未使能时读到1608，比1650下限低42计数；用户确认支撑可靠、无卡滞拉扯、可以回2047后，限定该轴在不超过60计数的偏差内按两次一致复读恢复。探查后ID32/33/34都已回中，保留扭矩。该许可不扩展其他轴的启动恢复范围。

指令行程和反馈范围分别处理：`hardware.json`的`tracking_feedback_range=device`仅让被跟踪接管的眼颈轴按已核验的EEPROM范围检查编码器，不改变面部其他轴的反馈规则。历史首轮ID33指令2107、反馈2113，仍在1600～2300内，不应因为超出当时的小范围6计数而中断整场；这类样本记入`feedback_outside_command_range_samples`，不伪装成已跟到目标。反馈真正越过设备范围仍立即停止，不增加额外编码器容差，指令与规划器也不得越过当前配置范围。

**小帅不要加`--parallel-neck on`**。ID32/33/34为独立左右、俯仰、翻滚，代码拒绝套用墨甲的并联机构与CAD参数；也不使用墨甲108像素画面偏置。浏览器打开`http://127.0.0.1:8765/`，观察绿框、眼球与三轴方向。请以现场观察核验首次眼球跟踪方向、翻滚跟随以及整体协调，固定轨迹成功不等同于联合跟踪已验收。

固定眉心相机采用绝对比例映射：图像位置决定眼球位置，不像眼内相机那样积分累积运动。眼球端点由`tracking.json`的EyeLook名称引用解析到原标定，再按设备限位裁剪，不再用过小的±60/±20试验幅度。没有相机内参和眼球角度标定时，这是相对注视映射，不宣称已经获得精确角度逆解。

眼球先响应图像偏差；已在动且偏差增大、或实测眼球已偏转时，颈部协助。固定相机下，眼球停在偏转位置也不会使招募机会失效；不再要求眼球必须重新运动才让脖子参与。俯仰复用同一规则，翻滚对人脸眼线的相对倾斜做轻微跟随，不把图像倾斜称为绝对人体姿态。丢脸或作品即将结束时平滑回中；相机或编码器反馈过期时先制动并保持，不用指令假装测量。单一串口控制者融合面部与跟踪目标，反馈优先照顾ID22/23/32/33/34。

日志中旧颈部参考速度峰值约105/71/19，低于旧硬件上限300/150/100，说明仅提升SRAM速度不能解决全部延迟。本轮上游左右、俯仰增益由120/80提升为360/240，翻滚目标趋近增益由1.5提升为3；左右参考加速度/jerk上限为1600/16000，俯仰和翻滚为800/8000，单位分别是计数/秒²、计数/秒³。这些是连续参考规划限制，不修改硬件加速度0。

检测使用320宽度推理并将框、关键点换算回原图，预览仍640×480；同一张已采集图片的本机对照约为640检测67ms、320检测并保留640预览20ms。它们是检测处理时间，不是整套跟踪延迟或真机动作达标证明，现场效果仍需复测。

ID32默认使用既有Ruckig上游轨迹，可用`--upstream-trajectory off`切回其150ms低通；ID33/34各自使用独立的有速度、加速度、jerk边界的同类轨迹。它们不是并联逆解，也不是原来的64计数/秒²软件限速。硬件加速度、PID、死区和扭矩保护不作本次调参。

口型仍有动态响应余量：此前600速度的日志ID31目标最低1916，稀疏编码器反馈最低1943，相对当时指令的95分位误差20计数；ID10、25约80、58计数。2026-11-07用户已要求把有效口部11轴默认速度统一改为900；由原启动流程写入并读回SRAM，原素材、标定、加速度和其他轴速度不变。

当前11个有效口部轴（10/11/12/13/15/25/26/27/28/30/31）在节目执行阶段统一直接发送映射目标，不再额外裁剪逐帧位置变化量；硬件运行速度均为900计数/秒，加速度寄存器原始值均为0。此设置同时用于歌曲、表情跟随和三个开发示例；不会强制电机瞬间到位，实际运动仍由舵机执行。眼睑仍600，低速回中仍60，初始接近、位置边界、自检和反馈保护保留。

设置来自本体`robot.json`的`defaults.mouth_command_mode=lips-direct`与`defaults.direct_mouth_scope=all`，轴清单从当前有效口部标定派生，不在节目代码硬编码。原`--mouth-command-mode lips-direct`指令继续有效，不显式传参也使用上述默认；名称兼容历史用法，实际范围以本体配置为准。墨甲未选`all`，仍使用原圆唇及下颌组。`--mouth-command-mode limited`仅用于需要时显式恢复软件限速对照。

## 3. 中位、限位与首轮处理

用户已确认表情零权重位置统一2047，ID31同样采用2047。ID24为颧骨轴，用户允许选择合理的可达回中位置：其设备上限2030，因此`hardware.json`保留`neutral=2047`作为换算基准，单独设置`home_position=2030`。

运行时区分两种含义：映射仍按2047计算位移，回中和命令范围检查使用可达目标2030。不会通过把零权重基准改成2030来改变表情换算公式。ID24在本标定中的唯一端点为2030，当前范围裁剪后作品1全程为2030，首轮不承担动态颧骨表现。

用户已选择按当前EEPROM限位裁剪。限位来自只读地址9～10（下限）、11～12（上限），两字节小端；它们是固件配置行程，不等同于机械挡块。源标定及设备限位没有改写。

标定31个端点超限、涉及18轴的完整清单见比较报告。实际作品1共有6774帧：ID5裁剪172帧、ID20裁剪143帧、ID21裁剪178帧、ID24裁剪6774帧，其余轴没有位置裁剪。裁剪不补造眨眼或静音闭嘴事件。

ID24曾读到未使能位置2045，比上限高15计数；仅在未使能、两次位置复读一致且偏差不超过20计数时允许按既有缓慢启动流程进入范围。所有发送目标仍位于1600～2030内，临时反馈通道仅用于准备阶段；实际目标和播放反馈限制不扩大。

首次启动只设置/核验本轮速度与已保存加速度，并沿用现有受限位置/使能流程；小帅配置未请求PID、死区、设备限位或相位改写。当前加速度原值为0；600是初始测试值，当前有效口部11轴已改为900，不宣称已经完成动态性能整定。

### 回中与播放的异常确认

小帅的`homing.json`显式启用`sensor_fault_confirmation`，回中运动反馈复用墨甲播放时的同轴、同类连续确认机制，阈值只读取`telemetry.json`：

| 情况 | 处理 |
|---|---|
| 电压越过设备范围，或电压报警位 | 同一轴连续4个完整有效样本仍异常才停止；正常读数清零计数。 |
| 温度超过100℃、温度报警、电流报警或过载报警 | 同轴同类连续4个完整有效样本才停止。 |
| 负载数值超过800、温度超过80℃ | 告警并记录。 |
| 缺包、坏包 | 不算作健康或故障传感器样本；沿用有界重读、两次有效确认及原通信错误率保护。 |
| 位置越界、型号/限位/速度单位不符、其他报警、人工停止 | 保留原检查，立即停止或拒绝启动。 |

回中发现待确认的传感器异常时保持最近合法目标，每隔20ms复读完整反馈，恢复后继续平滑回中；不会跨过缺失样本、改写报警数据或关闭舵机保护。回中前的配置快照、参数写入及独立读回仍严格检查。墨甲原有回中策略不因选择小帅而改变。

回中通信采用与播放一致的短寄存器反馈，并等待目标包线时及1ms间隔后查询。硬件限位、扭矩、电压和温度保护寄存器均不修改。一次报警不能证明误码；若连续确认后仍报电压故障，应检查供电。首轮回中日志曾记录ID11电压3.6V，低于其4.0V下限。

## 4. 外设与墨甲的区别

当前输出设备为`USB2.0 Device: Audio (hw:0,0)`，不使用墨甲USB音箱固定三倍音量档位。相机节点为`/dev/v4l/by-id/usb-RXSX_Technology_Co.__Ltd._USB_Camera_4K_RXSX001-video-index0`，用户确认固定于眉心。兼容入口的`--camera right`在本头只选用右眼编码器作为跟踪参考，并不表示相机安装在右眼；实际配置为`camera_mount=fixed`、`camera_eye=null`、`reference_eye=right`。

### 下颌适配与眼睑待验证项

现场首轮反馈为张嘴很小、眨眼不完全。日志显示ID31基本跟上了发送目标，但目标本身只有约1994～2050。该标定的50个通道引用ID31，其中49个端点均为2050，只有`JawOpen`为1850；采用墨甲的`all_calibrated`归一化，会让眉眼等近中位记录进入下颌的分母，明显压小张嘴行程。

小帅改用既有小白方案的`jaw_owner=JawOpen`，只让`JawOpen`控制下颌，公式为`2047 + JawOpen × (1850-2047)`。原始JSON全部条目保留，其他舵机仍使用原融合规则，墨甲配置不变。作品1的`JawOpen`原信号最高约0.666，因此新目标范围约1916～2047；这不是给信号加增益或要求每次都张到1850。此次只重算ID31，速度仍600，供用户单独对照。

眼睑5/6/20/21此次仍保持600。较长一次现场日志中，软件限速造成发送目标与映射目标最大约236计数差距；编码器相对发送目标的95分位误差约21～24计数。后者是稀疏反馈统计，不能表示每个眨眼峰值均已采样。另有端点被当前限位裁剪：ID5闭合1830→1850、ID20闭合2347→2330、ID21闭合1750→1780，ID6闭合2280仍可达。后续可单独对照眼睑速度1000，仍保留当前设备限位；提高速度不能补回被限位裁剪的闭合行程，不延长或重写源眨眼数据。

小帅与墨甲虽然都是52基础表情，但51个映射不同。小帅原标定含9/24，当前临时排除；29/35/36没有映射。眼睑闭合方向与墨甲相反；ID31张嘴端点1850，墨甲为1547。型号11272的历史小白记录包含ID31小幅运动及RAM42～47读回验证；小帅本体的实际表现以本次现场反馈为准。
