# 小帅（xiaoshuai）机器人配置

小帅：男性，28岁。本目录与`../mojia/`并列，用于保存小帅自己的标定及设备配置；控制算法继续共用`src/vivis/`。

## 1. 当前状态

已归档原始标定并完成设备只读查询，用户已确认ID31～34为SM45BL、舵机分布与小白相同；尚待确认中位及标定/设备限位差异。当前未部署可执行的`robot.json`，也未生成小帅的作品1播放目标。没有发送位置、使能或设备寄存器写入指令。

| 文件 | 用途 |
|---|---|
| `calibration.json` | 原始`小帅无色测试版6.22（16.24）.json`的逐字节副本，作为后续小帅运行标定来源。 |
| `calibration_comparison.json` | 对比墨甲全部52个表情、只读轴清单、限位冲突及待确认项的报告；这是查询证据，不是运行硬件配置。 |

本文中的设备限位来自本次串口只读EEPROM快照：下限地址9～10、上限地址11～12，均为小端两字节。例如ID3读到1547～2200，ID24读到1600～2030。它们是舵机固件采用的配置行程范围，与机构的机械极限分开记录；本次未修改这些值。

标定SHA256：`599fd7d1518ea0f35b40f7c3265c104fc68230a9027863449ccb8f496d3050ef`。标定本身没有声明零权重/回中位置，不能将表情权重1时的端点自动当作中位。

## 3. 首次播放前需要确认

1. 各轴的零权重/回中位置，尤其ID31是2047还是2050；ID24设备限位1600～2030不能容纳2047，需明确其实际中位或由标定同事核对限位。
2. 标定中31个端点超出当前设备限位，涉及18轴。需确认以现有限位裁剪，还是由标定同事核对更新设备限位；具体表情及数值见比较报告。

型号已于2026-11-05由用户确认：ID31～34为SM45BL，舵机分布与小白一致。历史小白配置同样是ID2～34、31～34型号值11272；旧ID31调试记录包含12计数运动和RAM42～47的位置/时间/速度读回核验。可据此复用寄存器访问方案，但这不代表已经在小帅上完成运动或物理速度验证。

另外，只读时ID33未使能，实测1507低于硬下限1600；ID24未使能，实测2045高于硬上限2030。这是被动位置读数，不能直接当作已确认的中位或已获允许的恢复范围。墨甲的ID29下颌避让/吐舌恢复和ID35被动偏移例外不自动继承。

## 4. 后续文件组织与作品1

确认后，在本目录补齐小帅专属`robot.json`、`hardware.json`、`homing.json`、`tracking.json`、`telemetry.json`及作品清单；每种设备参数只保留一个运行来源。现有加载器还固定要求墨甲35轴及其型号分组，启动恢复与结束清理也含墨甲专属ID29策略；需将这些核验和行为改为读取机器人配置，才能通过已有`--robot configs/robots/xiaoshuai/robot.json`接口选择小帅。示例及运行算法继续共用，不为每个机器人复制程序。

作品1使用现有`0001`的原音频和61通道源数据，按小帅标定及确认后的中位/限位重新生成专用舵机目标，保存到小帅命名空间。墨甲的`robot.json`、标定、目标轨迹与当前播放参数保持原版本。首轮建议先验收面部和音频，眼球/颈部跟踪在相机安装、方向及颈部拓扑确认后接入。
