# 小帅（xiaoshuai）：配置与作品1

小帅：男性，28岁。舵机分布同小白，设备清单为ID2～34共33轴：2～30读数521，31～34由用户确认是SM45BL，读数11272。配置和标定保存在本目录，控制代码与墨甲共用。

## 1. 首轮播放：面部＋完整音频

在项目根目录执行：

```bash
./examples/01_face_control/run.sh \
  --robot configs/robots/xiaoshuai/robot.json \
  --work 0001 --repeat 1 \
  --mouth-command-mode lips-direct --mouth-speed 600
```

末尾加`--check`仅做离线检查。首轮口部硬件速度上限600计数/秒，表情/圆唇增益均为1.0；每遍先以不超过60计数/秒缓慢准备25个面部轴，再从头播放完整作品1。显示`ROUND 1/1 COMPLETE`为本遍正常完成。

示例1不打开相机。眼球7/8/22/23、未映射29和颈部32/33/34不参与本模式的回中、位置发送或使能。停止沿用最后合法目标，不突然卸载受力机构；小帅不执行墨甲专属ID29吐舌恢复或结束卸载。

这些小范围用于首次联合验收，未改EEPROM限位。ID32回中前曾在未使能时读到1608，比1650下限低42计数；用户确认支撑可靠、无卡滞拉扯、可以回2047后，限定该轴在不超过60计数的偏差内按两次一致复读恢复。探查后ID32/33/34都已回中，保留扭矩。该许可不扩展其他轴的启动恢复范围。

**小帅不要加`--parallel-neck on`**。ID32/33/34为独立左右、俯仰、翻滚，代码拒绝套用墨甲的并联机构与CAD参数；也不使用墨甲108像素画面偏置。浏览器打开`http://127.0.0.1:8765/`，观察绿框、眼球与三轴方向。请以现场观察核验首次眼球跟踪方向、翻滚跟随以及整体协调，固定轨迹成功不等同于联合跟踪已验收。

眼球先响应图像偏差；已在动且偏差增大、或眼球已消耗部分行程时，颈部协助。俯仰复用同一招募规则，翻滚对人脸眼线的相对倾斜做轻微跟随，不把图像倾斜称为绝对人体姿态。丢脸或作品即将结束时平滑回中；相机或编码器反馈过期时先制动并保持，不用指令假装测量。单一串口控制者融合面部与跟踪目标，反馈优先照顾ID22/23/32/33/34。

ID32默认使用既有Ruckig上游轨迹，可用`--upstream-trajectory off`切回其150ms低通；ID33/34各自使用独立的有速度、加速度、jerk边界的同类轨迹。它们不是并联逆解，也不是原来的64计数/秒²软件限速。硬件加速度、PID、死区和扭矩保护不作本次调参。

口型仍有动态响应余量：最近一次日志ID31目标最低1916，稀疏编码器反馈最低1943，相对当时指令的95分位误差20计数；ID10、25约80、58计数。ID11/12/26/27的软件600限速还会压小短促目标。因此上面用`--mouth-speed 900`做单次速度对照，仍由原启动流程写入并读回SRAM，不改默认600、原素材、增益1.0或标定。该指令同时提升口部软件速度上限与硬件上限；7个直接口型轴仍保留硬件限速。眼睑当前仍600，闭合行程裁剪与眨眼速度需另轮验证，不声称联合跟踪解决了它们。

## 3. 中位、限位与首轮处理

用户已确认表情零权重位置统一2047，ID31同样采用2047。ID24为颧骨轴，用户允许选择合理的可达回中位置：其设备上限2030，因此`hardware.json`保留`neutral=2047`作为换算基准，单独设置`home_position=2030`。

运行时区分两种含义：映射仍按2047计算位移，回中和命令范围检查使用可达目标2030。不会通过把零权重基准改成2030来改变表情换算公式。ID24在本标定中的唯一端点为2030，当前范围裁剪后作品1全程为2030，首轮不承担动态颧骨表现。

用户已选择按当前EEPROM限位裁剪。限位来自只读地址9～10（下限）、11～12（上限），两字节小端；它们是固件配置行程，不等同于机械挡块。源标定及设备限位没有改写。

标定31个端点超限、涉及18轴的完整清单见比较报告。实际作品1共有6774帧：ID5裁剪172帧、ID20裁剪143帧、ID21裁剪178帧、ID24裁剪6774帧，其余轴没有位置裁剪。裁剪不补造眨眼或静音闭嘴事件。

ID24曾读到未使能位置2045，比上限高15计数；仅在未使能、两次位置复读一致且偏差不超过20计数时允许按既有缓慢启动流程进入范围。所有发送目标仍位于1600～2030内，临时反馈通道仅用于准备阶段；实际目标和播放反馈限制不扩大。

首次启动只设置/核验本轮速度与已保存加速度，并沿用现有受限位置/使能流程；小帅配置未请求PID、死区、设备限位或相位改写。当前加速度原值为0，600为首次测试的速度上限，不宣称已经完成动态性能整定。

### 回中与播放的异常确认

小帅的`homing.json`显式启用`sensor_fault_confirmation`，回中运动反馈复用墨甲播放时的同轴、同类连续确认机制，阈值只读取`telemetry.json`：

| 情况 | 处理 |
|---|---|
| 电压越过设备范围，或电压报警位 | 同一轴连续4个完整有效样本仍异常才停止；正常读数清零计数。 |
| 温度超过100℃、温度报警、电流报警或过载报警 | 同轴同类连续4个完整有效样本才停止。 |
| 负载数值超过800、温度超过80℃ | 告警并记录。 |
| 缺包、坏包 | 不算作健康或故障传感器样本；沿用有界重读、两次有效确认及原通信错误率保护。 |
| 位置越界、型号/限位/速度单位不符、其他报警、人工停止 | 保留原检查，立即停止或拒绝启动。 |

回中发现待确认的传感器异常时保持最近合法目标，每隔20ms复读完整反馈，恢复后继续平滑回中；不会跨过缺失样本、改写报警数据或关闭舵机保护。回中前的配置快照、参数写入及独立读回仍严格检查。墨甲原有回中策略不因选择小帅而改变。

回中通信采用与播放一致的短寄存器反馈，并等待目标包线时及1ms间隔后查询。硬件限位、扭矩、电压和温度保护寄存器均不修改。一次报警不能证明误码；若连续确认后仍报电压故障，应检查供电。首轮回中日志曾记录ID11电压3.6V，低于其4.0V下限。

## 4. 外设与墨甲的区别

当前输出设备为`USB2.0 Device: Audio (hw:0,0)`，不使用墨甲USB音箱固定三倍音量档位。相机节点为`/dev/v4l/by-id/usb-RXSX_Technology_Co.__Ltd._USB_Camera_4K_RXSX001-video-index0`，用户确认固定于眉心。兼容入口的`--camera right`在本头只选用右眼编码器作为跟踪参考，并不表示相机安装在右眼；实际配置为`camera_mount=fixed`、`camera_eye=null`、`reference_eye=right`。

### 下颌适配与眼睑待验证项

现场首轮反馈为张嘴很小、眨眼不完全。日志显示ID31基本跟上了发送目标，但目标本身只有约1994～2050。该标定的50个通道引用ID31，其中49个端点均为2050，只有`JawOpen`为1850；采用墨甲的`all_calibrated`归一化，会让眉眼等近中位记录进入下颌的分母，明显压小张嘴行程。

小帅改用既有小白方案的`jaw_owner=JawOpen`，只让`JawOpen`控制下颌，公式为`2047 + JawOpen × (1850-2047)`。原始JSON全部条目保留，其他舵机仍使用原融合规则，墨甲配置不变。作品1的`JawOpen`原信号最高约0.666，因此新目标范围约1916～2047；这不是给信号加增益或要求每次都张到1850。此次只重算ID31，速度仍600，供用户单独对照。

眼睑5/6/20/21此次仍保持600。较长一次现场日志中，软件限速造成发送目标与映射目标最大约236计数差距；编码器相对发送目标的95分位误差约21～24计数。后者是稀疏反馈统计，不能表示每个眨眼峰值均已采样。另有端点被当前限位裁剪：ID5闭合1830→1850、ID20闭合2347→2330、ID21闭合1750→1780，ID6闭合2280仍可达。后续可单独对照眼睑速度1000，仍保留当前设备限位；提高速度不能补回被限位裁剪的闭合行程，不延长或重写源眨眼数据。

小帅与墨甲虽然都是52基础表情，但51个映射不同。小帅9/24参与表情，29/35/36没有映射；眼睑闭合方向与墨甲相反；ID31张嘴端点1850，墨甲为1547。型号11272的历史小白记录包含ID31小幅运动及RAM42～47读回验证；小帅本体的实际表现以本次现场反馈为准。
